# Машинный контракт и расхождения с ТЗ


ТЗ и машинные контракты несовместимы в нескольких полях. Программа использует фактическую JSON Schema из архива, чтобы выдавать структурно допустимый результат:

| Текст ТЗ | Машинная схема и данные |
|---|---|
| `step_index`, `packet_time` | `step`, `decision_time`, `window_start`, `window_end` |
| `speed_limit_kph` | `speed_limit_kmh` |
| `target_stop_id` | `safe_stop_id` |
| отдельные действия запроса/освобождения оператора | булево `remote_support_required` в полном снимке |
| параметры срока HOLD и LIMIT_SPEED | поля срока отсутствуют, `additionalProperties=false` |
| перечень из пяти действий | дополнительно NO_ACTION для неактивных ВАТС |
| боковой ветер входит в ODD | код нарушения ветра отсутствует в enum |

При превышении ветра контроллер возвращает VIOLATED/HOLD с LOW_CONFIDENCE, не изобретая запрещённый код. Срок действия управления трактуется как один шаг до следующего полного снимка. Эти трактовки требуют согласования с организатором: сам ТЗ ставит свой текст выше машинной схемы. В архиве также нет полного официального оценщика или формулы нормирования action utility, поэтому локальные метрики нельзя выдавать за итоговый балл соревнования.
