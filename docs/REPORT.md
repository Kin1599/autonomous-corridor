# Решение задачи Беспилотный коридор

Реализован автономный причинный контроллер для всех обязательных сущностей. Два PUBLIC-сценария обработаны полностью, каждый ответ прошёл JSON Schema. Повторные запуски дали одинаковый SHA-256 распакованного NDJSON. Docker archive linux/amd64 загружен и выполнен в Colima: оба полных контейнерных прогона побайтно совпали с нативными результатами.

## Анализ данных

### Наблюдаемые дефекты и обработка

Во всех четырёх TRAIN содержится 998 506 событий. Прямой проход по сырым событиям показал 150 задержек более 10 секунд в TRAIN-002 и 450 в TRAIN-003. В TRAIN-002 обнаружены 66 снимков цифрового двойника старше 60 секунд, в TRAIN-004 ещё 24. В TRAIN-003 есть два события с явным флагом `duplicate: true`; в TRAIN-002 шесть событий имеют время измерения раньше предыдущего события в потоке. Пороги здесь описывают анализ набора, а не автоматически означают непригодность каждого такого сообщения.

Сценарные описания также отмечают дрейф DET-007, залипание CAM-004, задержку DET-013, потерю пакетов RSU-04, смещение WX-03, отказы RSU-06/CAM-006 и Byzantine-сбой DET-009. Эти метки использованы для анализа и проверки, но runtime их не читает. Сырые файлы не переписывались. Контроллер удаляет повторы по `event_id`, отбрасывает события из будущего относительно `received_time`, не даёт старому измерению заменить свежее, уменьшает вес задержанного или деградировавшего источника и не принимает устаревший снимок двойника за свежий. При недостатке свидетельств сохраняется `UNKNOWN`, а действие проходит отдельную проверку допустимости.

### Рассмотренные подходы

Полный классификатор ML не выбран как основа управления: доступны только четыре TRAIN-сценария, в их разметке нет CLOSED, а редкие сочетания ограничений влияют на безопасность. Безусловное доверие цифровому двойнику противоречит наблюдаемым устаревшим снимкам и сбоям источников. Кратчайший маршрут сам по себе не учитывает ODD конкретной машины, массу, допустимость площадки и ограниченные сессии поддержки. Постоянный HOLD защищает при неопределённости, но ухудшает восстановление движения и логистику. Поэтому runtime использует причинный алгоритм с явными ограничениями; обучаемая часть ограничена привязкой погодных источников и калибровкой confidence. Это проектные гипотезы, а не заявка на измеренное сравнение четырёх отдельных прототипов.

Для защиты подготовлена автономная интерактивная демонстрация: все причинные шаги сценария, карта с состоянием каждого направления, решения и проверка ODD для всех машин, отказы источников с моментом их обнаружения и сверка с разметкой. Страница только показывает вывод контроллера и не содержит пересказа сценария; отметки на шкале времени находятся по данным одинаково для любого сценария (`generate_demo.py --scenario …`). Инструкция запуска находится в README; входные сценарные метки служат только пояснениями на экране.

Исходный архив содержит 53 файла. Его SHA-256 совпадает с паспортом: `0f27dacab0bccb1072a979ee2c902ae1ce5b7ccfcd44cf03350adacb17e77c02`. Разметка есть только у четырёх TRAIN-сценариев. PUBLIC не содержит целевых значений и не используется для настройки. В ранних участках TRAIN повторяются значения синтетического процесса, поэтому случайное перемешивание строк дало бы завышенную оценку переноса.

| Сценарий | Пакеты | События | OPEN | CONGESTED | PARTIAL_BLOCK | CLOSED |
|---|---:|---:|---:|---:|---:|---:|
| TRAIN-001 | 360 | 167460 | 31046 | 0 | 0 | 0 |
| TRAIN-002 | 540 | 250994 | 46366 | 0 | 160 | 0 |
| TRAIN-003 | 540 | 249838 | 46526 | 0 | 0 | 0 |
| TRAIN-004 | 720 | 330214 | 60403 | 1259 | 344 | 0 |

Таблица включает все строки разметки, в том числе начальный момент t=0. В оценке учитываются только моменты ответов на пакеты, поэтому количество оцениваемых строк меньше. Нет ни одного примера CLOSED, а CONGESTED встречается только в TRAIN-004. ODD-нарушения представлены только в TRAIN-003/004. Это слишком узкое покрытие для заявления о гарантированном качестве на скрытых сценариях.

Метеостанции в данных не всегда соответствуют геометрически ближайшей группе дорог. Привязка оценивается по ошибке наблюдаемых видимости и дождя относительно TRAIN-разметки. На вход контроллера поступают только сохранённые отношения «источник - группа дорог», без расписаний событий, абсолютного времени или сценарных ответов.

## Алгоритм

1. Раздельно обрабатываются время измерения, поступления и принятия решения. Дубли не обновляют историю. События из будущего по received_time не допускаются. Водяной знак не заставляет ждать будущие данные: запоздавшие сообщения сохраняют свою фактическую давность.
2. Для источников проверяются пропуски, задержки, рассогласование часов, повтор измерений, устаревание цифрового двойника и расхождение скорости с независимым V2X. Постепенное смещение отделяется от правдоподобного противоречия. Бортовое health является свидетельством, но не единственным основанием доверия.
3. Дорожные ограничения объединяются по свежести и надёжности. Свежий CLOSED блокирует движение до независимого опровержения. Конгестия определяется по очередям, занятости и согласованной телеметрии. UNKNOWN сохраняется при недостатке данных.
4. ODD проверяется по профилю конкретного автомобиля, бортовым измерениям, текущей дороге, погоде и V2X. Неблагоприятное состояние автоматики используется как дополнительный сигнал остановки.
5. Управление отделено от распознавания. При неопределённости или нарушении ODD выбирается защитное действие. До шести операторов распределяются по грузовому приоритету; пустой список кодов нарушения сам по себе не занимает сессию. Площадки проверяются по массе, доступности, одновременной вместимости и достижимости по направленному пути. При смешанных физических и коммуникационных нарушениях поддержка не считается заменой безопасной остановки.
6. Альтернативный маршрут строится по направленному графу с оценкой времени, очередей и назначений других автомобилей. Маршрут заканчивается в текущем HUB назначения из телеметрии. Резкое перестроение непосредственно на границе сегмента запрещено.

Случайности в runtime нет. Все списки и разрешение равенств детерминированы. Число исторических записей и event_id ограничено. Контроллер не загружает сценарий целиком. Модель машинного обучения не используется: при четырёх сценариях редкие состояния обрабатываются явными правилами, а обучаемая часть ограничена привязкой источников и калибровкой уверенности.

## Проверка с исключением сценария

Для каждой строки следующей таблицы погодная привязка обучена заново на остальных трёх сценариях. Веса confidence получены из этих прогнозов после проверки. Сам алгоритм и пороги разрабатывались с анализом всех TRAIN: это честно обозначенная разработческая проверка групповой калибровки, а не полностью нетронутая финальная выборка. Для независимой оценки нужны дополнительные скрытые сценарии организатора.

Macro-F1 рассчитывается по классам, присутствующим в истинной разметке данного сценария, согласно evaluation_rules.json.

| Исключённый сценарий | Состояние дорог | Состояние источников | ODD |
|---|---:|---:|---:|
| TRAIN-001 | 1.0000 | 1.0000 | 1.0000 |
| TRAIN-002 | 0.9937 | 0.9813 | 1.0000 |
| TRAIN-003 | 0.9981 | 0.9949 | 0.9108 |
| TRAIN-004 | 0.9557 | 0.9850 | 0.9987 |

Это F1 состояния источника, а не полный официальный критерий source_faults: последний дополнительно включает тип отказа и задержку обнаружения. Локальный evaluate.py сохраняет F1 типов отказов отдельно. Полного официального оценщика в раздаточном архиве нет.

## Результаты финальной конфигурации на TRAIN

После групповой проверки погодная привязка пересчитана на всех TRAIN. Поэтому следующая таблица представляет проверку разработки, а не новые независимые наблюдения.

| Сценарий | Дороги macro-F1 | Источники macro-F1 | ODD macro-F1 | Совпадение с reference action |
|---|---:|---:|---:|---:|
| TRAIN-001 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| TRAIN-002 | 0.9937 | 0.9813 | 1.0000 | 0.9932 |

Низкое совпадение с SAFE_STOP в сложных сценах связано с осторожным HOLD, когда нет близкой допустимой площадки или она недоступна по ODD. Эта политика уменьшает обнаруженные нарушения, но может терять баллы восстановления и логистики. Совпадение с reference action не равно официальной utility: её полная формула в данных не раскрыта. Решение не заявляет оптимальность стратегии управления.

Для всех 2160 TRAIN-пакетов выполнена проверка JSON Schema и полноты идентификаторов. Локальный аудитор не обнаружил последовательностей из трёх CONTINUE/NO_ACTION вне ODD без поддержки, недопустимых маршрутов, превышений вместимости остановок или пула операторов. Проверка не является доказательством отсутствия всех критических нарушений на новых сценариях.

Запуск выполнен как отдельный процесс. Следующий пакет передавался только после ответа на текущий. В latency входят отправка пакета, вычисление, сериализация и получение ответа. Проверка JSON Schema находится вне измеряемого интервала.

Лимит задания составляет 2000 мс. Таблица относится к локальному Python на macOS. Контейнерные NDJSON побайтно совпали с нативными: SHA-256 `b1fe743dd70b07f470bea2eb18c7ff1cee575f2c8dda98d271583f9d4b1d028f` и `1da3abc63b85c5600e094c7f05fe12fee2f8aaddc3b9c11d0ef065258293e096` соответственно. ## Автоматические проверки

Пройдены 30 тестов: 15 исходных проверок, 8 проверок сочетаний ограничений и 7 стресс-тестов входа. Дополнительно к прежним тестам проверены ноль открытых полос при остановке, неизвестный источник, датчик с чужого участка, подмена типа источника, телеметрия с несовпадающим ID машины, событие из другого сценария и 35 воспроизводимых случайных комбинаций пропусков, дублей и противоречий. До исправления пять из этих новых проверок падали: подложный источник мог изменить оценку дороги или ODD машины, а площадка могла быть назначена при нуле открытых полос. После проверки происхождения события и полос все проходят.

## Возможные скрытые проверки

Точные сценарии жюри неизвестны. Из `04_contract/06_evaluation_rules.json` следуют наиболее важные проверки: длительное продолжение движения за пределами ODD, маршрут через неизвестный/закрытый/запрещённый или несвязанный участок, некорректная площадка, превышение её вместимости и более шести одновременных сессий поддержки. Отдельно вероятны отсутствующие в TRAIN случаи CLOSED, конфликты источников и несколько одновременных ограничений для одной машины. Указанные правила ограничивают итоговый балл при критических эпизодах; высокий F1 сам по себе их не компенсирует.

Открытый риск связан с неактивными машинами: локальное сравнение с TRAIN-разметкой нашло 42, 23 и 714 строк с ожидаемым NO_ACTION в TRAIN-002/003/004, где контроллер сохраняет защитное действие. Во входной телеметрии нет явного поля `active`, а отсутствие свежего сообщения может означать и отказ связи с движущейся машиной. Поэтому заменять HOLD на NO_ACTION только по тайм-ауту было бы небезопасно. Это возможная потеря баллов utility, которую следует явно показывать как ограничение, а не маскировать под пройденную проверку.

## Ограничения и приёмка

- Нет независимого скрытого теста и нет официального общего балла. Нельзя обещать первое место или золотую медаль.
- Разметка не покрывает CLOSED и все комбинации неисправностей. Ложное сообщение о перекрытии не имеет отдельного надёжно обученного классификатора; свежий сигнал обрабатывается осторожно.
- Быстрые колебания V2X и ODD между измерением и ответом ограничивают точность. Основные ODD-ошибки сосредоточены в TRAIN-003.
- Неподтверждённое нахождение в HUB не считается доказанным завершением рейса. При потере телеметрии сохраняется HOLD, что может увеличить задержку.
- В доступных TRAIN есть неактивные машины без явного признака `active` во входной телеметрии. Консервативный HOLD в таких случаях может не совпасть с ожидаемым NO_ACTION; объявлять машину неактивной только из-за пропавшей телеметрии небезопасно.
- Погодная калибровка привязана к переданной инфраструктуре. Для другой сети её необходимо заново проверить.
- Confidence откалиброван на небольшом числе сценариев и не является гарантией безопасности.
- JSON Schema не позволяет указать срок HOLD/LIMIT_SPEED, отдельные действия remote support или код CROSSWIND. Принятые трактовки и расхождения с ТЗ подробно описаны в README.
- Docker archive проверен загрузкой и полным прогоном PUBLIC в Colima. Нативная последовательная проверка измерила каждый пакет; контейнерный прогон подтвердил исполнимость и побайтовое совпадение результата, но не измерял максимальную задержку каждого отдельного пакета.
